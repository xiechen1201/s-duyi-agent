# 测试方案.md

## 开发和测试的顺序

TLD（传统模式），先开发功能，再编写测试用例。

TDD，先编写测试用例，再开发功能。后续编写功能的时候目标就是让测试用例通过。

## 测试方案

- 单元测试

单个函数，类是否正确

问题：只想测试函数本身，不想测试 session 等环境。如何屏蔽呢？

1、Stub 模式

桩模式，少见

测试期间肯定不能真实的发送验证码。如何做呢？写一个假的发送验证码的函数。

通过 monkeypatch 实现。

2、Mock 模式

传递 mocker 参数。

mocker.patch() 替换函数或类。

好处：可以统计函数调用次数。

以上就是为了解决单元测试屏蔽外部环境的问题。

- 集成测试

覆盖率 = 运行的测试代码 / 所有代码

一般是在全量测试的时候查看覆盖率。
