```python

async def generate_upload_sign(self, filename: str, file_size: int) -> dict:
        suffix = get_suffix(filename)
        if suffix is None:
            raise UploadException(f"无法获取文件后缀: {filename}")

        content_type = get_mime_type(suffix)
        if content_type is None:
            raise UploadException(f"不支持的文件类型: .{suffix}")

        if content_type not in IMAGE_MIME.values():
            raise UploadException(f"不支持的文件类型: {suffix}, 仅支持图片格式")

        oss_settings = await self._get_oss_settings()

        config = AliyunOSSConfig(
            access_key_id=oss_settings["oss_access_key_id"],
            access_key_secret=oss_settings["oss_access_key_secret"],
            bucket_name=oss_settings["oss_bucket_name"],
            endpoint=oss_settings["oss_endpoint"],
            mime_types=list(IMAGE_MIME.values()),
        )

        uploader = AliyunOSSUploader(config)
        credentials = uploader.generate_upload_credentials(filename, file_size)

        bucket_domain = oss_settings.get("oss_bucket_domain", "")
        if bucket_domain and not bucket_domain.startswith(("http://", "https://")):
            bucket_domain = f"//{bucket_domain}"

        credentials["bucket_domain"] = bucket_domain
        return credentials

```


generate_upload_sign 要做的两件事：

1、读取数据库中的一些设置（操作数据库）

2、调用公共库的方法（其他事情）

后续代码没有使用到数据库，但是数据库没有断开。

（既要操作数据库，又要操作别的事情，这个函数不再单纯）

带来一个什么问题？

进入函数的时候：db_session 事务启动

...操作

db_session 事务结束，归还链接

典型的长事务操作，哪怕有些耗时的操作也只能一直等待。

梳理整个链路：

```
运行 lifespan，直到 yield，准备好接收请求

请求到来=>

- 找到第一个中间件，将其进行执行放入到一个 try 中
  - 移交、移交、移交、路由（路由表）
  - 注入参数（params、query、body、DI）
  - 运行依赖函数得到生成器，迭代第一个 yield 的值（事务）
  - 迭代结果赋予参数 db_session
  - 路由函数执行（处于同一个事务环境）
  - 继续迭代生成器，直到全部迭代完成（自动提交、自动回滚、关闭事务）

  - 当一个中间件正常执行完成，把它返回的信息进行响应
  - 当地一个中间件执行错误，就进入异常处理
    - 根据注册的异常类型和对应的函数，找到函数执行
    - 响应函数的返回结果
    - 打印异常信息
```

如果 路由函数执行 的过程非常慢？（操作 IO），非常消费性能，这就是长事务的问题。

长事务的好处？强一致性，性能低。

短事务？高性能，无法保证一致性。

自由的选择长事务还是短事务？

```python
async def get_db() -> AsyncGenerator[AsyncSession]:
    session = get_session_factory()()
    session.begin()
    try:
        yield session
    except:
        await session.rollback()
        raise
    else:
        await session.commit()
    finally:
        await session.close()
```

```
await self.db.commit()
await self.db.close()
```

手动的提交和关闭事务。

后续使用 session.execute() 或者 flush() 方法，会自动开启事务（内部会发现没有连接了，自动开启事务）。

假设一个 api 调用多个 service， 只要其中一个 service 进行了一次 commit 和 close，那么整个长事务就自动变成了短事务。

对于那些非常重要的数据，宁愿消耗性能，也要保证一致性。

那些一般的数据，可以选择短事务，以提高性能，要进行动态的抉择。
